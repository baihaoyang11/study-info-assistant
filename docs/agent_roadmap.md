# Study Info Assistant：自主学业待办目标

## 用户目标与当前基线

2026-10-12，用户指定 GitHub 仓库 https://github.com/baihaoyang11/study-info-assistant，并要求后续开发持续同步代码。目标是自主查看 QQ 邮箱和 Canvas，每半天整理一份待办清单送达用户。

基线：QQ 指定邮件头只读读取、CLI、Mock、56 项离线测试和一次真实读取 3 封邮件头的验收已完成。Canvas 当前仅接口与 Mock。没有后台采集或自动摘要任务已运行。

## 实现方向

1. 只读采集：QQ 正文通过 PEEK 获取，忽略附件；Canvas 在学校允许的 API/OAuth 或获准浏览器会话范围内读取课程、作业、公告和日历，不自动提交作业、不发起测验。
2. 本地 SQLite：邮件按账号、UIDVALIDITY、UID 去重；Canvas 按来源类型和远端 ID 去重。同步成功后再提交游标，失败时保留上次成功数据并报告来源状态。
3. 统一待办：标题、课程、事项类型、截止时间/时区、来源链接或邮件引用、待确认原因、完成状态。时间不明确时不猜测，保存来源证据供用户核对。
4. 半日清单：新增事项、未来 7 天截止、逾期未完成、时间待确认、来源读取失败。重新运行不重复新增，同一待办可更新截止时间，用户标记完成后不自动重新打开。
5. 定时运行：先接入当前聊天的半日自动任务或本机运行器；默认候选时间为 Asia/Shanghai 每天 09:00、21:00，待用户确认送达渠道与时间。频繁采集与半日推送是两个独立调度，不把每次采集都通知用户。
6. GitHub：每个完成并通过测试的功能提交/推送；CI 只跑离线测试。代码、合成测试数据和文档可同步，真实邮件、数据库、摘要、日志和凭证不进入仓库。

## 待补充的接入信息

- Canvas 网址与学校批准的接入方式；Token 仅在本机配置，不写入聊天、代码或 Git。
- 清单送达位置与时间；若选择 QQ 邮箱，需要独立的摘要发送模块，收件人固定为用户本人，采集连接器继续保持只读。
- 常驻主机：本机任务依赖机器运行；如果要在关机时继续查看，需要另行选择常驻服务器部署和凭证存储方案。

## 验收目标

- 无凭证时离线 Mock 可以完整生成合成待办清单。
- 同步、事项提取、去重、截止时间更新、完成状态和半日摘要有 pytest 覆盖。
- 真实 QQ 与获准 Canvas 接入分别验证，失败不能被显示成“没有待办”。
- 用户指定渠道实际收到一份清单；之后才将自动任务报告为已启用。
- GitHub 远端提交包含已验证的代码，不含本机私有数据；CI 结果单独确认。
